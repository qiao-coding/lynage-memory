# Lynage Memory 架构详解

> 术语见 [00-terminology.md](00-terminology.md)

## 核心思想

```
传统方案：  消息 → 太多了 → 压缩成摘要 → 原文丢弃 ❌
Lynage：   消息 → 太多了 → 原文归档 → 窗口带摘要标签 → 需要时打开窗口读原文 ✅
```

## 全景数据流

```
   用户输入 ──────────→  lynageStreamText()
                         │
                         ├─ ① startTurn()  ──→ 保存 user 消息
                         ├─ ② streamText() ──→ 调用 LLM
                         └─ ③ finishTurn() ──→ 保存 assistant 消息
                              │
                              └─ 检查: 当前对话是否超出 Token 阈值?
                                   │
                                   ├─ 未超出 → 继续
                                   └─ 超出 → 旧对话冻结成窗口
                                               └─ 窗口加入阶段
                                               └─ 阶段满 → 升代

              ┌─────────────────┼─────────────────┐
              ▼                 ▼                 ▼
        ┌──────────┐    ┌──────────────┐   ┌──────────────┐
        │ 消息      │    │ 窗口          │   │  阶段         │
        │ (原文)    │    │ (冻结的对话)   │   │  (窗口容器)    │
        │          │    │              │   │              │
        │ msg-1    │    │ 🗂 窗口 #1    │   │ 📁 G0 → 🗂   │
        │ msg-2    │    │ 🗂 窗口 #2    │   │ 📁 G1 → 📁   │
        │ ...      │    │ 🗂 窗口 #3    │   │ 📁 G2 → ...  │
        └──────────┘    └──────────────┘   └──────────────┘

              ┌─────────────────┴─────────────────┐
              ▼                                   ▼
        ┌────────────┐                     ┌────────────┐
        │  工作记忆   │                     │  用户画像    │
        │ (当前任务)  │                     │ (长期偏好)   │
        └────────────┘                     └────────────┘
              │                                   │
              └───────────────┬───────────────────┘
                              ▼
                    ┌──────────────────┐
                    │     编译器        │──→ LLM 看到的精简文本
                    └──────────────────┘
```

## 七层结构（自底向上）

```
  Layer 7  编译器              给模型看的"精简视图"
  Layer 6  用户画像             长期不变的偏好和约束
  Layer 5  工作记忆             当前任务状态便签
  Layer 4  升代                阶段嵌套（G0→G1→G2）
  Layer 3  阶段                窗口的容器（工作区/阶段）
  Layer 2  窗口                冻结的对话片段（带摘要标签）
  Layer 1  消息                原文地基（永不丢失）
```

### 概念关系

```
工作区: React 组件库开发
  ├── 阶段: 前期开发
  │     └── 窗口 #1: 技术选型讨论 (消息 msg-1 ~ msg-84)
  └── 当前对话 (未冻结的消息)
```

---

## Layer 1：消息 — 永不丢失的原文

这是最底层。每条消息是一条记录，追加写入，从不修改。窗口只是"框"——框住了一段消息范围。

```
用户视角:   🗂 窗口 #1 (第 1~42 轮: 技术选型)
系统内部:   msg-1  "我要做组件库..."
           msg-2  "建议用 TypeScript..."
           ...
           msg-84 "好的，开始迁移 Tailwind"

窗口 = msg-1 到 msg-84 这段范围。
原文在消息表中，永不丢失。
```

```
┌──────────────────────────────────────────────────┐
│ messages 表                                       │
├────────┬──────────┬─────────┬────────────────────┤
│ id     │ role     │ content │ createdAt          │
├────────┼──────────┼─────────┼────────────────────┤
│ msg-1  │ user     │ 你好     │ 2026-07-25 09:00  │
│ msg-2  │ assistant│ 你好！   │ 2026-07-25 09:01  │
│ msg-3  │ user     │ 帮我...  │ 2026-07-25 09:02  │
│ ...    │ ...      │ ...     │ ...                │
│ msg-N  │ ...      │ ...     │ ...                │
└────────┴──────────┴─────────┴────────────────────┘
```

**关键字段**：`sourceFromId` / `sourceToId` 形成精确定位链，确保可以找回任意一段原文。

## Layer 2：窗口 — 冻结的对话片段

当前对话超过 Token 阈值时，旧对话被「冻结」成一个窗口。

```
        活跃窗口太大（> 16K tokens）
              │
              ▼
    ┌─────────────────────┐
    │ 找自然边界            │  不能切断 Q&A 对
    │ (boundary-detector) │  不能切断 Tool调用/结果
    └────────┬────────────┘
              │
              ▼
    ┌─────────────────────┐
    │ 旧对话 → 冻结成窗口    │
    │ AI 生成窗口摘要标签    │
    └────────┬────────────┘
              │
              ▼
    ┌──────────────────────────────────────────────┐
    │ 上下文窗口 #028                               │
    ├──────────────────────────────────────────────┤
    │ 摘要:    "讨论数据库方案，决定用 SQLite"        │
    │ 关键词:   [SQLite, WAL, Drizzle]              │
    │ 内容范围: 第 42~55 轮对话                      │
    │ 原文:     ✅ 已保存，随时可打开阅读              │
    └──────────────────────────────────────────────┘
```

**用户看到的是上下文窗口。系统内部用 msg ID 精确定位原文。**

## Layer 3：阶段 — 窗口的容器

```
窗口 #1
窗口 #2     }──→  太多了，建个阶段来管理
窗口 #3
窗口 #4
窗口 #5

变成:

    📁 工作区: React 组件库开发
    ├── 🗂 窗口 #1: 技术选型
    ├── 🗂 窗口 #2: 初期开发
    ├── 🗂 窗口 #3: 样式迁移
    ├── 🗂 窗口 #4: 重构
    └── 🗂 窗口 #5: 新功能
```

**阶段 = 窗口的容器**，记录了这段时间项目推进了什么、形成了什么结论。

---

## Layer 4：升代 — 阶段嵌套

一个阶段下的窗口太多(20个) → 创建上层阶段来概括它们。

```
之前：                         之后：
  📁 工作区                     📁 工作区
  └── 📁 (20 个窗口)             ├── 📁 阶段: 前期开发
                                │     摘要: "架构设计阶段"
                                │     └── 📁 (20 个窗口, 降级)
                                └── (新窗口继续往这里加)

再归档 → 又装满 20 个 → 再升代：

  📁 工作区: React 组件库开发
  ├── 📁 阶段: 前期开发 (第 1~120 轮)
  │     摘要: "架构设计、组件开发和样式迁移"
  │     └── 20 个窗口
  └── 📁 阶段: 架构重构 (第 121~180 轮)
        摘要: "monorepo 重构、团队扩展"
        └── 20 个窗口
```

**升代 = 阶段套阶段。每个窗口都可以展开看到原文。**

---

## Layer 5：Working Memory — Agent 的便签纸

记录"现在做到哪了"，每轮对话自动注入。

```
┌─────────────────────────────────┐
│ Working Memory                  │
├─────────────────────────────────┤
│ currentTask    设计数据库方案     │
│ confirmed      SQLite + WAL     │
│ confirmed      Drizzle ORM      │
│ progress       已确定存储方案     │
│ unresolved     阈值设为多少？     │
└─────────────────────────────────┘
         │
         ▼  每次调用 LLM 时自动注入
    "# Working Memory
     Current Task: 设计数据库方案
     Confirmed: SQLite + WAL, Drizzle ORM
     ..."
```

---

## Layer 6：User Memory — 长期不变的用户画像

跨任务、跨会话的稳定信息。

```
┌─────────────────────────────────┐
│ User Memory (user-001)          │
├─────────────────────────────────┤
│ preferences    回答简洁直接       │
│ preferences    技术判断严谨       │
│ constraints    不用向量数据库     │
│ constraints    不绑定特定厂商     │
│ background     7年全栈开发       │
└─────────────────────────────────┘
```

**和 Working Memory 的区别**：User Memory 很少变（用户偏好、长期约束），Working Memory 每轮都可能变（当前进度、未决问题）。

---

## Layer 7：Context Compiler — 编译给模型看的视图

6 种场景，编译不同内容：

```
场景                 编译内容
──────────────────────────────────────────
normal-chat         User + Working + Recent Messages
project-work        加上 Directory 摘要 + 未解决问题
history-search      验证后的候选原文 + 置信度
source-verification 候选原文全文 + query 对照
archive-indexing    Chunk 原文 → 摘要 Prompt
worker-search       项目快照 + 子目录（并行搜索用）
```

## 搜索流程

```
lynageSearch("为什么放弃语义分类？")
        │
        ├─ ① FTS5 搜所有窗口摘要 + 原文 → 找到匹配窗口
        ├─ ② 目录下钻 Root → G1 → G0 → 窗口 #028
        ├─ ③ 打开窗口 #028，验证原文是否真的匹配 → 置信度 85%
        └─ ④ 把窗口内容编译进当前 LLM 上下文
```

**用户看到：在所有历史窗口中搜索 → 找到 → 打开阅读。**

**模糊搜索**：创建 SearchTask → 分批检查目录 → 保存游标 → 跨轮次继续。

**并行搜索**：主进程创建快照 → N 个 Worker 并发读不同目录 → 合并去重 → 原文验证 → 演变链重建。

## 记忆写回

```
AI 回复附带 memoryActions
        │
        ▼
  ① JSON 解析
  ② Zod Schema 校验（target/operation/section/value）
  ③ Lynage 语义校验（不能覆盖原文、不能删目录、不能推测当事实）
  ④ 数据库事务写入
        │
        ├─ target="workingMemory" → working_memory 表
        └─ target="userMemory"    → user_memory 表
```

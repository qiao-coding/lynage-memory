# 全程推演：一次对话的完整生命周期

> 术语见 [00-terminology.md](00-terminology.md)
>
> 场景：用户正在开发一个 React 组件库。假设归档阈值 = 2000 tokens。
>
> 核心概念：
> - **工作区** = 一个项目，比如"React 组件库开发"
> - **窗口** = 工作区下的一段冻结对话，比如"技术选型讨论（第1~42轮）"
> - **阶段** = 窗口太多时创建的分组容器

---

## 第 1 轮 · 项目启动

```
用户: "我要做一个 React 组件库，帮我设计技术方案"
AI:   "建议用 TypeScript + Vite 构建，组件用函数式写法..."
```

**此时各层状态：**

```
工作区: React 组件库开发
  └── (还没有窗口，对话刚开始)

当前活跃对话:
  ┌──────────────────────┐
  │ 第 1 轮               │
  │ 用户: 我要做组件库...   │
  │ AI: 建议用 TS+ Vite.. │
  └──────────────────────┘

Working Memory:
  (空)
```

---

## 第 30 轮 · 第一个决策确定

```
用户: "那就用 CSS Modules 吧，简单"
AI:   "好的。已在工作记忆中记录。"
```

**此时各层状态：**

```
工作区: React 组件库开发
  │
  ├── (窗口尚未产生 — 对话还没超出 Token 阈值)
  │
  └── 当前活跃对话: 第 1~30 轮 (~1600 tokens)
        ├── "我要做组件库..."
        ├── "建议 TypeScript + Vite..."
        ├── ...
        └── "用 CSS Modules 吧"

  Working Memory:
    currentTask    开发 React 组件库
    confirmed      使用 CSS Modules
    confirmed      TypeScript + Vite 构建
```

---

## 第 50 轮 · 第一次产生窗口

当前活跃对话超出 2000 Token 上限。系统找到第 42 轮末尾的自然边界，把第 1~42 轮「冻结」成工作区下的第一个窗口。

```
工作区: React 组件库开发
  │
  ├── 🗂 窗口 #1: 技术选型讨论 (第 1~42 轮)
  │     摘要: "确定了 CSS Modules + TypeScript + Vite 的技术栈"
  │     关键词: [技术选型, CSS Modules, Vite, TypeScript]
  │
  └── 当前活跃对话: 第 43~50 轮 (~400 tokens)
         ├── "Button 组件怎么设计?"
         ├── "用函数式组件 + forwardRef..."
         └── ...

  Working Memory:
    currentTask    开发 React 组件库
    confirmed      CSS Modules, TS + Vite
```

**Working Memory 更新：**

```
之前:                          之后:
┌──────────────────────┐      ┌──────────────────────────┐
│ confirmed:            │      │ confirmed:                │
│  CSS Modules          │      │  Tailwind CSS    ← 更新   │

└──────────────────────┘      │                          │
                              │ recentChanges:           │
                              │  CSS→Tailwind   ← 新增   │
                              └──────────────────────────┘
```

## 第 100 轮 · 工作区下积累多个窗口

又触发了 2 次归档。当前工作区下有 3 个窗口。

```
工作区: React 组件库开发
  │
  ├── 🗂 窗口 #1: 技术选型讨论 (第 1~42 轮)
  │     摘要: "确定 CSS Modules + TS + Vite"
  │     关键词: [技术选型, CSS Modules]
  │
  ├── 🗂 窗口 #2: 初期组件开发 (第 43~82 轮)
  │     摘要: "完成 Button、Input、Modal 基础组件"
  │     关键词: [Button, Input, Modal, 组件设计]
  │
  ├── 🗂 窗口 #3: 样式方案迁移 (第 83~92 轮)
  │     摘要: "从 CSS Modules 切换到 Tailwind CSS"
  │     关键词: [Tailwind, 样式迁移, CSS Modules]
  │     重要变更: CSS Modules → Tailwind
  │
  └── 当前活跃对话: 第 93~100 轮

  Working Memory:
    currentTask    开发 React 组件库
    confirmed      Tailwind CSS, TS + Vite, 函数式组件
    progress       已完成基础组件, 正在迁移样式

```

## 第 120 轮 · 工作区下窗口太多 → 分组

工作区下积累了 20 个窗口。系统把它们分组——创建一个「阶段」来概括前半段。

```
┌──────────── 之前 ────────────┐    ┌──────────── 之后 ────────────┐
│                              │    │                              │
│ 工作区: React 组件库开发       │    │ 工作区: React 组件库开发        │
│   ├── 🗂 窗口 #1         │    │   │                          │
│   ├── 🗂 窗口 #2         │    │   ├── 📁 阶段: 前期开发        │
│   ├── ...                    │    │   │    │ 摘要: "完成技术选型、  │
│   └── 🗂 窗口 #20        │    │   │    │  基础组件和样式迁移"   │
│                              │    │   │    │                     │
│  20 个窗口平铺，难以概览   │    │   │    ├── 🗂 窗口 #1    │
│                              │    │   │    ├── 🗂 窗口 #2    │
│                              │    │   │    ├── ...              │
│                              │    │   │    └── 🗂 窗口 #20   │
│                              │    │   │                          │
│                              │    │   └── (新窗口继续往这里加)  │
└──────────────────────────────┘    └──────────────────────────────┘

一个父类上下文 (工作区) 拥有:
  - 若干子类上下文 (阶段)
  - 每个阶段下又有若干子类上下文 (冻结的对话窗口)
```

---

## 第 160 轮 · 从窗口找回信息

团队壮大，需要找回之前关于 monorepo 的讨论。

```
用户:  "团队 5 个人了，之前那个 monorepo 方案现在可以做了"
AI:    "让我查一下之前是怎么讨论的..."

lynageSearch("monorepo")
  → 在当前工作区的所有窗口中搜索 "monorepo"
  → 找到 窗口 #1: 技术选型讨论 (第 1~42 轮)
  → 打开 窗口 #1，阅读当时的对话原文
  → 发现: 第 25 轮决定不做 monorepo（"过早优化"）

AI:    "找到了。之前在 窗口 #1 (技术选型讨论) 里，
        第 25 轮我们决定不做 monorepo，理由是只有 3 个包。
        现在有 5 个包了，条件已满足。"
```

**搜索过程：**

```
lynageSearch("monorepo")
    │
    ├─ ① 在当前工作区的所有窗口摘要中搜索 "monorepo"
    │      → 窗口 #1 的摘要匹配
    │
    ├─ ② 打开 窗口 #1，验证原文
    │      → 确认原文确实在讨论 monorepo
    │      → 置信度 90%
    │
    └─ ③ 把 窗口 #1 的对话内容加载到当前 LLM 上下文
           → LLM 现在能看到当时的完整讨论
```

```
  ├── 📁 阶段: 前期开发 (第 1~120 轮)
  │     摘要: "完成技术选型、基础组件和样式迁移"
  │     重要结论: [SQLite, Tailwind, TS + Vite]
  │     │
  │     └── 🗂 20 个窗口 (技术选型、组件开发、样式迁移...)
  │
  ├── 📁 阶段: 架构重构 (第 121~180 轮)

  │     重要结论: [monorepo 架构, 分包策略]

```

```
lynageSearch("样式方案 不用了")
  → 在工作区下搜索所有窗口
  → 找到 3 个可能相关的窗口
  → 创建持久化搜索任务

┌──────────────────────────────────────┐
│ 持久化搜索任务                        │
├──────────────────────────────────────┤
│ 工作区: React 组件库开发              │
```

## 关键理解

```
一个工作区 (父类上下文)
  │
  ├── 一个阶段 (子类上下文，可嵌套)
  │     │
  │     └── 一个冻结的对话窗口 (子类上下文)
  │           包含: 第 N~M 轮的所有消息
  │           摘要: "这段对话讨论了什么"
  │
  ├── 另一个阶段...
  │
  └── 当前活跃对话 (尚未冻结)

搜索 = 在工作区的所有窗口中找
Worker = 拿着工作区快照，读分配给自己的窗口
写回 = 主进程读完窗口原文后，确认结论，更新工作记忆
```

# Lynage 是什么

## 一句话

Lynage Memory 是 Agent 的记忆模块。它保存每一句对话原文，给旧对话贴上摘要标签方便查找，需要时打开原文确认事实——**摘要只是索引，原文才是记忆。**

---

## 先说什么不是

Lynage **不是**传统的上下文压缩。

```
传统压缩:                          Lynage:

原文 → 摘要 → 丢掉原文 ✅           原文 → 摘要标签 → 原文保留
       ↑                                  ↑         ↑
  摘要就是记忆                        标签只是索引   原文才是记忆
  (原文丢了，回不去了)                 (原文永远在)   (随时可以回去读)
```

打个比方：
- **传统压缩** = 把一本书烧了，留一张内容简介。简介说啥你就只能信啥。
- **Lynage** = 给每本书贴个标签，书还在书架上。想看的时候顺着标签找到书，翻开来读。

标签可以写得不够好、漏了一些信息——没关系。打开书就什么都清楚了。

---

## 核心概念

```
工作区: React 组件库开发          ← 一个项目
  │
  ├── 阶段: 前期开发               ← 窗口太多时的分组
  │     │
  │     ├── 窗口 #1               ← 一段被冻结的对话 (第 1~42 轮)
  │     │     标签: "讨论技术选型，确定 CSS + TS + Vite"
  │     │     原文: msg-1 ~ msg-84 (完整保留)
  │     │
  │     └── 窗口 #2               ← 另一段被冻结的对话
  │           标签: "Button 组件开发，遇到 hover 样式问题"
  │           原文: msg-85 ~ msg-130
  │
  ├── 阶段: 架构重构
  │     └── ...
  │
  └── 当前对话                     ← 还没冻结的最近消息
        用户: "之前那个样式方案为什么不用了？"
        AI 做的事:
          ① 在所有窗口标签中搜索 "样式方案"
          ② 找到窗口 #1 和 #2 的标签匹配
          ③ 打开窗口 #1 的原文 (msg-1~msg-84)
          ④ 在原文中确认: "CSS Modules 不支持动态样式 → 决定切 Tailwind"
          ⑤ 回答用户: "因为 CSS Modules 不支持动态样式..."
```

## 术语速查

| 术语 | 是什么 | 不是什么 |
|------|--------|---------|
| **消息** | 一条对话记录，追加写入，永不修改 | — |
| **窗口** | 一段被冻结的对话，带 AI 生成的摘要标签。原文完整保留 | 不是传统压缩的摘要——标签丢了也能从原文重建 |
| **阶段** | 一组窗口的容器。窗口太多时建阶段来分组 | 不是固定的项目分类——按时间和容量自动生长 |
| **升代** | 阶段满了 → 创建上层阶段概括下层。G0→G1→G2 | 不是删除旧阶段——只是套了一层，原文始终可达 |
| **工作记忆** | 当前任务状态便签："正在做什么、已确定什么、还没解决什么" | 不是完整历史档案——只是当前状态 |
| **用户画像** | 跨任务的稳定信息："偏好简洁、不用向量数据库" | 不是项目级配置——是用户级的长期约束 |
| **归档** | 当前对话超出 Token 阈值 → 冻结旧对话为窗口 | 不是压缩丢弃——原文保留，只是不再每次塞给 LLM |
| **搜索** | 在所有窗口的标签中匹配关键词 → 打开原文确认 | 不是只看标签就信——标签只用来找，确认靠原文 |
| **写回** | LLM 读原文后，把确认的结论写入工作记忆 | 不是 LLM 随便改——经过 Zod+语义双重校验 |

---

## 关键理解

**Lynage 不替代原文。它只是帮你在一堆对话里快速找到相关的那一段，然后让你自己读原文确认。**

标签是工具，原文是事实。
